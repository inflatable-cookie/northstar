## Standards and Specifications

### Standard Readme
- **Repository**: https://github.com/RichardLitt/standard-readme
- **Type**: Community specification
- **Confidence**: High
- **Notes**: Defines standard sections for README files. Badge conventions. Style guide.

### Awesome Readme
- **Repository**: https://github.com/matiassingers/awesome-readme
- **Type**: Curated examples
- **Confidence**: Medium
- **Notes**: Collection of exemplary README files. Good for identifying patterns.

## Badge Services

### Shields.io
- **URL**: https://shields.io/
- **Type**: Service
- **Confidence**: High
- **Notes**: De facto standard for README badges. Customizable via URL parameters. Multiple styles (plastic, flat, flat-square, for-the-badge, social).

### Badgen
- **URL**: https://badgen.net/
- **Type**: Service
- **Confidence**: Medium
- **Notes**: Alternative to shields.io. Faster badge generation. Smaller SVGs.

## Generation Tools

### Readme So (readme.so)
- **URL**: https://readme.so/
- **Type**: Web-based editor
- **Confidence**: Medium
- **Notes**: Drag-and-drop README editor. Templates for common sections.

### Various CLI Tools
- `readme-md-generator` - Interactive CLI for Node.js projects
- `make-a-readme` - Web-based generator
- Language-specific generators (often tied to package scaffolding)

## README Sections (Common Patterns)

1. **Title/Header** - Project name + description
2. **Badges** - Build status, version, license, coverage
3. **Description** - What the project does
4. **Installation** - How to get it
5. **Usage** - Basic usage examples
6. **API/Documentation** - Link to full docs
7. **Contributing** - How to contribute
8. **License** - License information
9. **Acknowledgments** - Credits

## Key Questions This Source Map Should Answer

1. What sections are truly universal vs project-specific?
2. How can templates support both structure and flexibility?
3. What badge conventions should be supported?
4. How do we avoid README drift over time?
