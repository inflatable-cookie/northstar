## Generation Intent and Boundary

`g01` was Northstar's first live self-hosting roadmap generation. Its boundary
was internal Northstar-on-Northstar enactment: establishing the live `docs/`
spine, capturing the delivery-layer and autonomy doctrine, promoting copy-ready
templates into `template-bundle/`, aligning installable skills, adopting the
automation runtime policy, and proving autonomous execution with ready-state and
closeout mechanics.

## Shipped Outcomes by Durable Capability

### Live docs spine

Established the standard Northstar repository structure (`docs/architecture/`,
`docs/contracts/`, `docs/roadmaps/`, `docs/logs/`, `docs/vision/`), defended by
the repository contract checker.

### Delivery layer and execution autonomy

Captured the delivery-layer execution grammar
(`vision -> research/specs -> architecture + contracts -> roadmap milestone -> execution -> evidence -> closeout`)
and autonomy boundaries, ensuring that execution proceeds against canonical
authority rather than unpromoted conversational notes.

### Reusable template bundle

Promoted minimum copy-ready surfaces into `template-bundle/`: specs README and
templates, working-rules contract, and product guardrails.

### Automation runtime policy

Established the automation runtime hierarchy: Effigy first; repo-owned scripts
in Bun/TypeScript (and later Rhai); Bash and Python minimized to explicit
exceptions. Migrated the live checker lane off legacy Bash.

### Ready-state rubric and closeout pattern

Defined the ready-state rubric for individual cards and autonomous continuation
chains; established the mechanical end-of-lane closeout sequence (card ->
roadmap -> log -> handoff -> next task).

## Material Migrations, Compatibility Limits, and Retained Risks

- **Checker migration:** Migrated live repository checkers from Bash to
  Bun/TypeScript during Batch 2.2 (card 010); subsequently transitioned to Rhai
  in `g02`.
- **Compatibility policy:** Removed legacy Bash checkers from live paths without
  backward-compatibility shims, conforming to pre-1.0 clean-break rules.
- **Retained risks:** Ready-state selection and closeout mechanics reduce but do
  not eliminate ambiguity when strategic direction changes; governed by stop
  conditions.
