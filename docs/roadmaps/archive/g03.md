## Generation Intent and Boundary

`g03` made Northstar compact by default. One strict task lifecycle replaced
milestone and card hierarchies. Machine-owned JSON records replaced
agent-written status prose, the Queue closeout hook took over mechanical
bookkeeping, and closed generations shrink to a roll-up. Its boundary was the
lifecycle, its adapters and the portfolio rollout of those adapters. Product
planning in consumer repositories stayed outside it.

## Shipped Outcomes by Durable Capability

### Compact lifecycle and flat task units

Lifecycle-bound artifacts replaced permanent live-tree history (`g03.001`,
`g03.002`). Milestones and cards flattened into one generation task unit
(`g03.003`).

### Portable lifecycle core and hook-owned closeout

A portable core with deterministic projections replaced agent-written
mechanical bookkeeping (`g03.005`, `g03.006`). The Queue closeout hook
publishes terminal records, regenerates projections and removes consumed
handoffs in one integration commit (`g03.007`, `g03.008`). Hooks run through
Effigy and the installed skill, with no copied runtime in consumers
(`g03.010`).

### Generation state separation and parallel projections

An exhausted generation stays open in `planning_required` until an explicit
closure record (`g03.009`). Projections represent legitimate parallel active
generations (`g03.011`). Closed-generation task fragments compact into one
verified receipt (`g03.018`).

### Sole-source currentness

Lifecycle JSON and generated regions are the only mechanical currentness.
`audit-currentness` blocks duplicate status headers and stale frontier prose
(`g03.012`). Terminal closeout converges to one lifecycle authority
(`g03.021`).

### Transient handoff backlink guard

The backlink guard stays bounded on large repositories (`g03.013`–`g03.015`).
It rejects backlinks to a transient worker handoff at the accepted PR head
before merge (`g03.017`). Its cost now scales with the files that match, not
with corpus size (`g03.022`).

### Queue prospective merge

Pre-merge checks accept prospective-merge events without weakening prior
contracts (`g03.019`). Prospective merge became the portable Queue default,
migrated across the adopted portfolio (`g03.020`).

### UI design delivery and protocol reduction

Material UI design decisions move before dispatch, with rendered exact-head
review (`g03.004`). Repeated protocol enumerations shrank and redundant modes
retired (`g03.016`).

## Material Migrations, Compatibility Limits, and Retained Risks

- Superseded: `g03.016`'s mandatory `Oracle gate` in ready manifests was
  replaced on 2026-09-14 (`7caa986`) by an optional, operator-approved second
  opinion. Ready manifests no longer carry an Oracle disposition.
- Thirty-one adopted consumers run `paseo.queue.control.v4` with
  `prospective_merge`, resolving one shared installed adapter.
- The six consumers left red after the rollout were repaired on 2026-09-24
  (`docs/logs/2026-09/17-102000-prospective-merge-consumer-rollout.md`).
- Retained risk: the installed skill is Queue's pinned adapter identity, so any
  skill change moves a pinned digest.
